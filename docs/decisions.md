| ID | Date | Decision | Why |
|---|---|---|---|
| D-001 | 2026-11-10 | Target **UE 5.7** | Multi-process Learning Agents training (many game processes → one trainer) needs 5.6+. Unreal-MCP is CI-tested on 5.7. The v26 toolchain targets Rocky Linux 8, the same OS as Cradle. |
| D-002 | 2026-11-10 | **Learning Agents (PPO)** as the RL stack. AMD Schola is the fallback. | Native, policies run in the shipped game, no containers needed. The RL layer stays separate so a swap is possible. |
| D-003 | 2026-11-10 | **C++** for all logic; Blueprints only for data and wiring | Diffable, reviewable, editable by Claude. |
| D-004 | 2026-11-10 | **Original maps only**, built from JSON specs plus a procedural generator. No copies of Riot's maps, names or assets. | Avoids IP problems, and randomized layouts reduce overfitting. |
| D-005 | 2026-11-10 | **Fair observations** (line of sight only) plus adjustable human-likeness settings | The end goal is in-game opponents; the settings can be relaxed for research. |
| D-006 | 2026-11-10 | **Train ONLY against scripted bots.** The deathmatch is a field test, never training. | User decision. Agent-vs-agent play is evaluation only. |
| D-007 | 2026-11-10 | Unreal-MCP in **local mode** (no ai-game.dev account) | Editor data stays on the machine. |
| D-008 | 2026-11-11 | **No local training**; all training runs on Cradle | User decision. |
| D-009 | 2026-11-11 | **The GitHub repo (private) is the only channel between LOCAL and CLUSTER.** Markdown docs plus commits and pushes after each advancement. Binaries (builds, snapshots) travel via GitHub Releases. Claude Code runs on both sides; the LOCAL session never SSHes into Cradle. | The cluster's security policy; the user works on both sides in parallel. |
| D-010 | 2026-11-11 | The UnrealMCP plugin is **not committed**; it is reinstalled with `unreal-mcp-cli` | ~580 MB of binaries, editor-only, never needed on the cluster. |
| D-011 | 2026-11-11 | Level geometry (the range, later the maps) is **spawned at runtime from data in C++** (`FPSArena`), not authored as `.umap`. The startup map is the empty engine `/Engine/Maps/Entry`. | One code path for the editor and headless Cradle; per-episode procedural variants need no repackaging; no LFS assets. MCP is used for preview and play-testing. |
| D-012 | 2026-11-11 | Mechanics tuning lives in `UFPSAgentSettings` (text config, `DefaultGame.ini`), not in DataAsset `.uasset` files | Diffable, mergeable, readable by both sides of the repo. |
| D-013 | 2026-11-11 | Input actions and mapping are **built in C++ at runtime** (no input assets) | Same reason as D-012; works in any build without content. |
| D-014 | 2026-11-11 | Map format v1 is a **tile grid (4 m tiles) with elevation in 1 m levels**. Ramps are the only way up; drops are one-way; the walkable graph must be strongly connected. | User wanted elevation from the start. A grid keeps generation, validation, line of sight and previews simple. |
| D-015 | 2026-11-11 | The procedural **pool is generated offline in Python** (validated), shipped inside the build as JSON, and **C++ picks a map per run or episode by seed** (`-Map=pool`) | Python is fast to iterate and test; the cluster gets new layouts with no Unreal work. |
| D-016 | 2026-11-11 | Play-time switches are **console variables** (`fps.PlayMap`, `fps.TopDown`, `fps.ShowHitboxes`) | Unreal-MCP's console tool runs against the editor world, so they must be global to be scriptable. |
| D-017 | 2026-11-11 | Sightline "close" floor calibrated **0.30 → 0.20** | Tile-pair sampling makes pairs under 10 m geometrically rare; extra cover on map01 moved it only 0.23 → 0.25. The long cap (≤ 30%) is the gameplay-relevant guard. |
| D-018 | 2026-11-11 | Spike A uses a **toy reach task with the real bean** (`-Stage=SpikeA`). The game **only ever connects to an external trainer** (never spawns one), and the editor always plays back. **Resume = the game loads the `.bin` snapshots before connecting** (weights only). | It proves the whole stack (Linux build, CharacterMovement headless, socket trainer, snapshots) with a task the scripted baseline solves at 100%. External-only enforces hard rule 6. The trainer takes its starting networks from the game, so this is the only resume path in 5.7. |
| D-019 | 2026-11-11 | **One policy step = one fixed 60 Hz tick**, in training (Learning Agents sets it) and in headless playback (we set it) | Without it, `-nullrhi` ticks at about 1 800 Hz with real-time deltas, so "360 steps" meant 0.2 s and episodes were meaningless. |
| D-020 | 2026-11-11 | **Trainer first, games after `Server listening on`; never probe the trainer port.** The game has a wall-clock connect watchdog (exit 1). | The 5.7 trainer wedges on a connection that closes without a config, and the engine's connect timeout ignores time spent in blocking `connect()`. |
| D-021 | 2026-11-11 | **Everything the CLUSTER side produces lives under `~/beanRant/`**, next to the repo (not inside it): `builds/<sha>/`, `runs/<run-id>/` (snapshots, game and trainer logs, TensorBoard), `logs/` (Slurm output) and `envs/la-train` (conda prefix env). Weka (`/weka/scratch`) is not used for now. The only files outside are `gh`'s login in `~/.config/gh`. Replaces the `~/fps-agent/...` and `<weka>/...` paths. | User decision: one folder holds the whole project on a shared account. Home is NFS with 36 TB free, and Spike A outputs are small. Revisit (new entry) if outputs outgrow the home quota or NFS I/O slows runs. |
| D-022 | 2026-11-12 | **An episode's end is a pure function of the current state** (checked in `GatherAgentCompletion`), never a flag set while computing the reward. **One-off bonuses are paid at most once per episode.** **Run lengths are given in experience batches** (`-Batches=N` = N × `IterationsPerGather` gradient iterations). | Learning Agents 5.7 calls `GatherCompletions()` before `GatherRewards()` each step. Spike A's flag-based completion ended episodes one step late and paid the reach bonus twice (C-004). The trainer's `IterationNum` counts gradient iterations, 32 per batch, which hid how short "150 iterations" was (C-005). |
| D-023 | 2026-11-12 | **Combat stages decide 15 times per second** (a decision every 4th fixed 60 Hz tick, action held in between), with **discount 0.995** (a setting; sweep 0.99–0.997). All combat stages share one observation and action layout. Spike A keeps one decision per tick (D-019). | At one decision per tick with γ = 0.99, the agent looks only about 1.7 s ahead, so a clear bonus 20 s away is worth about 6e-6. At 15 Hz with 0.995 it looks about 13 s ahead. A shared layout lets each stage resume from the previous stage's snapshot (resume = weights only). Research: `docs/research/rl-reward-and-optimization.md` §2. |
| D-024 | 2026-11-12 | **Hard rule 4 gets two human-equivalent exceptions (user's explicit OK):** (1) a **hit indicator**: the direction damage came from, when the agent is hit; (2) **hearing**: enemy gunshots and footsteps within a radius, as direction + rough distance + age, with the same rules the scripted bots use. Everything else stays line-of-sight-in-FOV or a ≤ 2 s memory. | Human players get both cues. Without them an agent shot from behind has no information, while the bots (fair senses) can hear it. Inputs must be fixed before S0 training, because adding them later forces retraining from scratch. |
| D-025 | 2026-11-12 | **`-Set=Path=Value;...` overrides any `UFPSAgentSettings` field at startup** (reflection; numbers, bools, struct text). It's applied once in `AArenaGameMode::InitGame`, before anything reads the settings. An unknown path or bad value exits with code 2. | Sweeps over reward weights and PPO knobs need no new build (spec §6); a typo must fail loudly, not train with defaults. |
| D-026 | 2026-11-12 | **Combat training passes `bResetAgentsOnUpdate=false`** to `RunTraining`. A reset that Learning Agents starts while our episode is still running (start of training, its step cap) is not recorded as an episode and not counted by the ramp. Spike A keeps `true`. | Combat episodes last up to 20-90 s. Resetting every arena at each policy update would cut most of them short and feed the difficulty ramp false failures. |
| D-027 | 2026-11-12 | **Default training job until the S0 build is measured: N = 4 games × K = 32 arenas, trainer `--batch-size` = N, on the GPU, `-c 8` (about 2 cores per game), 1 GPU.** Re-run Spike B's sim mode on the first S0 build, and revisit after C-007. (D-025 and D-026 are reserved by LOCAL's Build A plan.) | Spike B (`docs/spikes/B-throughput.md`, 25 training runs). The trainer, not the games, sets the pace: about 3.9 s per update, of which 2.2 s is fixed gradient work and 1–2 s is three 1-second polls in the trainer's socket code (shortening them cut 15–31%). `--batch-size 1` drops (N−1)/N of the simulated experience; `--batch-size N` uses about 80% of it. With the stock PPO settings (32 iterations per update, fixed minibatches), more experience per update didn't learn faster. Up to 80 k steps per update learned about as fast; at 160 k, 2 of 3 runs didn't reach +9 in 25 batches. So N stays at 4 (40 k). The stock CPU trainer is single-threaded and took 2.0–2.3× longer per batch than the A100. One game process gives 16–27 k agent-steps/s at K = 16–64 on about 2 cores. |
| D-028 | 2026-11-12 | **Combat timeouts are a Termination, not a Truncation** (changes spec §3). The fixes from the final build A review also freeze these observation details before S0 trains: the enemy vector gains fine aim channels (aim error / 5°, clamped; 15 values), the field of view is also checked vertically (70.53° = 103° horizontal at 16:9), and playback resets the policy memory at every new episode, as training does. | The time left is observed and the clear bonus depends on it, so the time limit is part of the task (Pardo et al. 2018). Truncation would bootstrap from a time-left = 0 state the critic never trains on, and Φ = 0 at the end would leave an uncancelled −Φ. Aim error / 180° made a head at 15 m (0.46°) an input of 0.0025, with no observation normalization in the trainer. The layout and end semantics can't change after S0 trains without retraining from scratch. |
| D-029 | 2026-11-12 | **The pinned trainer carries one patch: three socket polls shortened** (user's OK, C-007 (1)). In `learning_agents/communicators/socket_communicator.py`, `receive_experience` 1 → 0.01 s, `_sender` 1 → 0.05 s and `_worker` 1 → 0.01 s. Every other trainer file stays verbatim from UE 5.7.4. The patch is marked in the code and listed in `cluster/learning_agents_python/README.md`. | Spike B: the trainer, not the games, sets the pace, and these 1 s sleeps were 1–2 s of each ~3.9 s update. CLUSTER measured the same patch at 15–31% fewer seconds per batch with all games normal (job 151931). It is three numbers with no new logic and is easy to undo or re-apply on an engine upgrade. |
| D-030 | 2026-11-12 | **D-027's job stays the default for combat S0, now measured on `build-10520b5`: N = 4 games × K = 32 arenas, `--batch-size 4`, 1 GPU, `-c 8`, about 300 batches per 2 h chained job.** `cluster/slurm/combat.sbatch MODE=train` runs it and chains jobs through `chain.txt`. | Spike B on combat (L-007 (2), jobs 152032–152035; `docs/spikes/B-throughput.md` → *Combat build A*). `PPO train` costs a fixed 11.3–12.0 s per update for every N and K (Spike A: 2.2 s): the memory + attention policy, overhead-bound at 3–12% GPU. So seconds per batch grow only with N: 19 s (N = 4), 20–21 s (N = 8), 24–25 s (N = 16). More experience per update didn't learn faster per update, here or in Spike A. K = 32 is the fastest game per process (3,050 decisions/s against 2,055 at K = 8), and one round of 32 × 300-step episodes fits `ReplayMaxSteps` 10,000. 5 static bots instead of 1 cost 19–21% of game speed. Revisit N = 4 against N = 8, and `IterationsPerGather` / `PolicyBatchSize`, once S0 learns (compare on `-Eval`). |
| D-031 | 2026-11-13 | **Build B (S1 "Movers") design rulings** (plan `docs/superpowers/plans/2026-11-13-combat-build-b-s1.md`): (1) the S1 spawn rule "a tile no bot can see" is met by placing bots around the agent with the stage knobs and turning each to **face away**, so the agent is outside every view cone, even on an open floor; (2) cover changes per episode by moving a **pool of cover blocks**; the floor is built once; (3) **Investigate moves only Patrol/Explore bots**, while Static/Strafe/Peek/Crouch bots turn to face the stimulus and hold their spot; (4) **Peek needs a hidden/exposed tile pair** near the bot (tile line of sight from the agent), and without one the bot strafes; (5) the agent hears enemy sounds for **1 s** (newest first, up to 4); (6) a **gate-level clear rate `clearTop`** (non-review episodes at level ≥ 0.95) is logged, and the promotion trigger becomes mean level ≥ 0.9 **and** `clearTop` ≥ the gate for 10 windows; (7) `-Scripted` in S1 stands and shoots when an enemy is in sight, otherwise explores and investigates heard sounds. | (1) Spec §5 asks for an unseen spawn, but at difficulty 0 there is no cover to hide behind, so view cones are the fair, always-possible way; facing away also gives the agent the first shot, a gentle start. (2) Spawning and destroying geometry every episode would churn actors and the garbage collector at 32 arenas. (3) Keeps easy bots predictable while movers make the floor feel alive. (4) A peek without cover would just be a strafe. (5) Matches the bots' reaction-plus-memory window. (6) In S0 the old trigger fired at 67% while the gate needs 70% (L-007 note (a)). (7) Spec §6 says S1 moves with Hunt logic, but Hunt is an S3 behaviour; Explore plus Investigate is its S1 subset. |
